# CI and delivery

Development CI runs on PRs to `dev` or `main`, pushes to `dev` or `main`, and manual dispatch. The required check names are `branch-policy`, `quality`, `unit-and-contract-tests`, `streamlit-smoke`, and `ci-gate`.

The test job uploads `reports/junit.xml` even on failure. The gate writes a job summary with each dependency result. The smoke job starts `app/Home.py`, probes `/_stcore/health`, captures the log on failure, and stops the process. PR code runs with read-only workflow permissions. `branch-policy` checks that PRs target `dev` or `main` and originate from a branch in this repository. Phase integration PRs to `main` must come from `dev`; inspect issue blockers separately before planned work.

When pytest finds a failing test, the `unit-and-contract-tests` job fails at **Run pytest**. GitHub shows that named check in red, even if the other jobs pass; the always-run `ci-gate` also fails and its job summary lists the failed dependency. The test job still uploads `reports/junit.xml` for inspection. This behavior was observed in the intentional probe [PR #3](https://github.com/Artfever/FleetpulseAI/pull/3): its [CI run](https://github.com/Artfever/FleetpulseAI/actions/runs/42505100210) reported 1 failing probe and 2 passing tests, with `unit-and-contract-tests` and `ci-gate` failed. PR #3 was closed without merging; it verified the failure path and added no product behavior.

Task PRs target shared `dev` and do not require teammate approval. The `dev` branch requires the five checks, an up-to-date base, and resolved conversations, but no teammate approval. Protected `main` requires a PR from `dev`, one approving teammate review, resolved conversations, and all five checks with the branch up to date. Stale approvals are not automatically dismissed, and approval after the latest push is not separately required. Force pushes and deletion are disabled on `main`, and its protection applies to administrators. Verify settings with `gh api repos/Artfever/FleetpulseAI/branches/main/protection` and `gh api repos/Artfever/FleetpulseAI/branches/dev/protection`.

Streamlit Community Cloud should be configured for this repository, branch `main`, entrypoint `app/Home.py`, and Python 3.12. The account owner must connect the repository in Streamlit Community Cloud. A reviewed merge to `main` will trigger its normal source update; post-merge Actions checks report failures but cannot hold back a deployment that has already started. Remote hosting is not verified until the live app and commit are observed.
